## Recommendation (summary)

Ship a **data-driven YAML/JSON matrix** under `tests/quality_matrices/` with a **unified
rule index** that maps native IDs (lint registry code · Schematron pattern id · encode
theme/row) into matrix slots. Shared loaders + three thin runners (lint / convert /
validate). Pilot = **METAR/SPECI**. CI = **PR smoke subset** + optional full-matrix
marker. Empty slots are explicit `needs-fixture` (inventory gate fails on silent gaps).
No new package, no new dependency (reuse `pyyaml` via `tac2iwxxm`), no network/Supabase.

This is a **session design note** (S02.L1 / E30-T8) — not a standing ADR unless M1
forces a shared public API change.

## Evaluation answers (#831)

### 1. Case storage

| Option | Verdict |
|--------|---------|
| pytest `@parametrize` tuples in Python | Reject for bulk — poor reviewability at 20×N |
| **YAML/JSON under `testdata/` + pytest load** | **Adopt** (E30-T2=1) |
| Extend golden catalogs only | Reject as sole SoT — goldens are product-happy-path, not 5×4 rule budgets |

**Shape**: one file (or small family) per rule or per engine×product, e.g.

```text
tests/quality_matrices/
  loaders.py
  runners/          # M1
  testdata/
    lint/metar_speci/<RULE_CODE>.yml
    convert/metar_speci/<ENCODE_ID>.yml
    validate/metar_speci/<SCH_PATTERN_ID>.yml
  inventory/        # unified index (T0.2 → M1 gate)
```

### 2. Rule inventory source of truth

**Adopt unified index** (E30-T3=1): one inventory document/artifact that *points at*
native SoTs without replacing them:

| Engine | Native ID | Upstream SoT |
|--------|-----------|--------------|
| lint | `IssueSpec.code` | `tac_validate.issue_registry.ISSUES` (ADR-028) |
| validate | Schematron `pattern/@id` | `vendor/.../rule/iwxxm.sch` (pin via manifest) |
| convert | encode theme / annex3 case id | `tac2iwxxm` annex3 / theme map rows |

Inventory rows map each native ID → 20 matrix slots (or `needs-fixture` / OOS cite).

### 3. Granularity

| Engine | One matrix rule = |
|--------|-------------------|
| lint | One registry **issue code** (e.g. `INVALID_VISIBILITY`) |
| validate | One Schematron **pattern id** (e.g. `METAR_SPECI.AerodromeHorizontalVisibility-1`) |
| convert | One **encode theme / fixture stem** that exercises a distinct encode branch (e.g. `metar_nil`, `metar_cavok`, `speci_nsc`) — not “every XML element” |

Cross-links in the unified index are optional annotations (e.g. lint `INVALID_RVR` ↔ SCH
`METAR_SPECI.AerodromeRunwayVisualRange-1`); they do not collapse engines into one runner.

### 4. Assertions

| Bucket intent | Assert |
|---------------|--------|
| lint happy / edge-pass | Accept (no blocking error) **or** expected info/warning codes present |
| lint sad / edge-fail | Expected **code** (+ severity class) present |
| convert happy / edge-pass | Encode succeeds; optional golden / content signals; soft residuals OK if declared |
| convert sad / edge-fail | Encode raises / returns typed failure as declared |
| validate happy / edge-pass | XSD+SCH pass (or only allowlisted failed-assert ids) |
| validate sad / edge-fail | Expected failed-assert pattern id (or XSD error class) |

Default for pilot: **exact diagnostic codes / SCH pattern ids**. IWXXM fragment XPath and
residual emptiness are **opt-in per case** (`expect.xml_xpath`, `expect.residuals_empty`) —
not required for every slot.

### 5. Product scope first

**METAR/SPECI first** (S02.M1), then deepen other products via inventory-gated expansion
(TAF → SIGMET family → advisories). Do **not** thin-cover all products before finishing
the pilot runners + inventory gate.

Pilot lint in-scope: registry codes tagged `metar`/`speci` (or shared aerodrome parse
gates used by METAR/SPECI). Exclude SIGMET/VAA/TCA/SWXA-only codes from M1 inventory.

### 6. CI cost

**PR smoke subset** (pilot rules / marked cases) + **optional full-matrix** via pytest
marker / `make` target (E30-T7=1). Full matrix may run nightly or on-demand — not every PR.

### 7. Filling 5×4 when natural examples are scarce

Priority order:

1. Reuse / lightly mutate existing accept/negative fixtures under `tac-validate` /
   annex3 goldens.
2. Author **synthetic TAC** that still targets one rule.
3. Mark slot `status: needs-fixture` with reason — **inventory gate fails** if a slot is
   missing entirely (silent gap). `needs-fixture` skips/xfails the runner but **counts**
   as tracked for the gate.

Do not duplicate entire WMO example trees ×20.

## Runner API (spike → M1)

```python
@dataclass(frozen=True)
class RuleCase:
    rule_id: str          # native id (code / sch pattern / encode id)
    engine: str           # "lint" | "convert" | "validate"
    bucket: str           # "happy" | "sad" | "edge_pass" | "edge_fail"
    case_id: str          # "01".."05" (zero-padded)
    tac: str | None
    status: str           # "ready" | "needs-fixture" | "oos"
    expect: dict          # codes / sch_ids / pass|fail / optional xpath
    meta: dict            # optional cites, product, notes
```

**Node id**: `{rule_id}/{bucket}/{case_id}` (pytest node id / param id) — TC-F29-005.

**Skip policy**: `needs-fixture` → `pytest.skip` (or xfail if marked flaky); `oos` → skip
with cite in message. Inventory gate treats both as explicit, not silent.
